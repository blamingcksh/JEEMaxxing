OPTION & SOLUTION FIGURES (same mechanism, different fields)

    "solutionImage": {"imageRef":"a2","cropBox":{...}}   (bare tag string also OK)
  Renders above the worked solution in the solution popup.
- One figure per option letter, at most one solution figure per question.
- All the coordinate rules below apply identically to these refs.

COORDINATE RULES (the app crops EXACTLY this region — be precise)
- x,y = top-left corner of the diagram as FRACTIONS of the screenshot's
  width/height. Range [0, 1].
- w,h = width/height of the crop region as FRACTIONS too. Range (0, 1].
- Coordinates are relative to the FULL original screenshot as uploaded, never
  a downscaled preview.
- Add ~1–2% padding around the diagram so the crop never clips its border.
- Keep x+w ≤ 1 and y+h ≤ 1. Out-of-range boxes get clamped — sloppy = cut figures.
- If the diagram spans the whole screenshot: { "x":0, "y":0, "w":1, "h":1 }.
- If a question has NO diagram inside a screenshot, OMIT both fields entirely.
- When unsure of the exact region, prefer a slightly LARGER box (the user can
  still re-crop manually) over a too-small one that amputates the figure.

─────────────────────────────────────────────────────────────────────────────────────────────────
CRITICAL: MANDATORY JSON & LATEX ESCAPING RULES (MEMORIZE THIS)
─────────────────────────────────────────────────────────────────────────────────────────────────
When generating raw JSON, EVERY LaTeX backslash inside a string MUST BE 
DOUBLE-ESCAPED (`\\`). Single backslashes in JSON string values get 
interpreted as control characters, breaking UI/KaTeX rendering or causing fatal JSON parse errors.

APPLY THIS TO ALL JSON STRINGS ("stem", "hint", "explanation", "answer", "options"):

1. ENVIRONMENTS (matrices, aligns, cases):
   - Wrap the ENTIRE \begin{env}…\end{env} in ONE pair of delimiters — $$ … $$ for a standalone/display block, or $ … $ when it sits inline in a sentence.
   - NEVER split \begin{...} and \end{...} into separate math groups, and NEVER emit <LaTex> / <LaTex> style tags — the app doesn't understand them.
   - Remember the escape ladder: row break \\ in the parsed string → emit \\\\ in your raw JSON.

2. THE ESCAPE LADDER (this is where stems break):
   Desired result             | Parsed string contains | Raw JSON you emit
   LaTeX command              | \frac                  | \\frac
   Matrix/align ROW BREAK     | \\                     | \\\\
   Visual line break in text  | <newline char>         | \n

   - NEVER emit raw `\\n`. It parses to literal backslash+n and KaTeX
     paints a red "\n" error mid-stem (e.g. "\nList", "\nFind").
   - NEVER emit raw `\\` immediately before a digit or space. It parses
     to a single `\`, collapses matrix rows, and paints red "\1" / "\0".
   - The double-escape rule applies to LATEX COMMAND BACKSLASHES ONLY.
     A newline is a JSON escape, not a LaTeX command: emit it as \n.

3. HARD JSON CRASHES (Invalid Escapes):
   In JSON, a single backslash `\` MUST be followed by `"`, `\`, `/`, `b`, `f`, `n`, `r`, `t`, or `u`.
   If you output a single backslash before ANY OTHER letter, the JSON parser will FATAL CRASH.
   - `\alpha`, `\angle` -> `\a` (CRASH)
   - `\cos`, `\cap`, `\cup` -> `\c` (CRASH)
   - `\sum`, `\sin`, `\subset` -> `\s` (CRASH)
   - `\lim`, `\le`, `\lambda`, `\left` -> `\l` (CRASH)
   - `\pi`, `\pm`, `\partial` -> `\p` (CRASH)
   - `\int`, `\in`, `\iota` -> `\i` (CRASH)
   - `\mu`, `\mathbb{R}`, `\mathrm` -> `\m` (CRASH)
   - ALWAYS double-escape: `\\alpha`, `\\cos`, `\\sum`, `\\in`, `\\mathbb`.

4. SILENT CORRUPTIONS (Valid JSON Escapes that break LaTeX):
   You MUST also watch out for these common LaTeX commands that map to valid JSON escapes but corrupt the math:
   - `\theta`, `\tau`, `\tan`, `\times` -> JSON reads `\t` (TAB) -> renders as `heta`, `an`.
   - `\neq`, `\nabla`, `\neg`, `\not` -> JSON reads `\n` (NEWLINE) -> renders as `eq`, `abla`.
   - `\phi`, `\forall` -> JSON reads `\f` (FORM FEED) -> renders as `hi`, `orall`.
   - `\right`, `\Re` -> JSON reads `\r` (CARRIAGE RETURN) -> renders as `ight`.
   - `\bar`, `\because` -> JSON reads `\b` (BACKSPACE) -> renders as `ar`.

5. TEXT-MODE vs MATH-MODE BLEED:
   If a special character appears OUTSIDE of `$ ... $` math delimiters, it MUST be escaped (double-escaped in JSON):
   - Dollar signs (currency): "Cost is $5" MUST be `Cost is \\$5`. (Else LaTeX enters math mode and breaks).
   - Percentages: "Efficiency is 50%" MUST be `Efficiency is 50\\%`. (Else LaTeX comments out the rest of the string).
   - Ampersands & Underscores outside math: `\\&` and `\\_`.

6. CHEMISTRY & UNITS:
   - Do NOT use `\ce{}` (mhchem) unless the UI explicitly supports it. Use `\\text{H}_2\\text{O}` or `\\mathrm{H_2O}`.
   - NEVER emit raw unicode math glyphs. Always use LaTeX commands: ≠ \\neq, ≤ \\le, ≥ \\ge, ± \\pm, × \\times, ∞ \\infty, ≡ \\equiv, → \\to, ° ^\\circ, µ \\mu.

7. NO LITERAL NEWLINES IN JSON:
   Never press "Enter" to create a physical line break inside a JSON string value. This causes a `Control character in string` fatal error. Use `\n` for UI line breaks or keep the string on one continuous line.
